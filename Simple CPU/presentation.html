Project Implementation Structure

Core Files

The executable logic is divided into four distinct C source files. We will strictly focus on how these files operate natively.

1. registers.c

Allocates the simulated memory array, creates global variables representing hardware registers, and handles masked write limits.

2. fetchDecodeExecute.c

Implements the core machine loop functions. Manages program counter incrementing and opcode isolation via bitwise operations.

3. instructions.c

Contains the specific algorithmic definitions for the 15+ supported instructions, memory pointer handling, and ASCII visualization.

4. assembler.c

Provides the `sscanf` based string-parsing engine that builds 16-bit binary integers out of human-written text.

Hardware State Simulation

registers.c

This file allocates the state variables used by the entire processor. Standard integer types simulate size-specific hardware constraints.

  • Memory: Simulated as a massive array: int memory[4096] (providing 8192 bytes total capacity).
  • 16-bit Registers: AC (Accumulator), IR (Instruction Register), and MBR.
  • 12-bit Registers: PC (Program Counter) and MAR (Memory Address Register) since max address is 4095.
  • 8-bit Registers: InREG and OutREG for standard I/O processing.
// registers.c globals int cpuClock = 0; int AC = 0, IR = 0, MBR = 0; int PC = 0, MAR = 0; int InREG = 0, OutREG = 0; int data_bus = 0; int memory[4096];

Enforcing Hardware Limitations

registers.c

C integer variables are usually 32-bits, but our CPU must behave strictly according to 8/12/16-bit boundaries. This file uses MASK macros (e.g., & 0xFFFF) during every write to forcefully truncate overflows.

The CPU Clock

Notice that every single setter function (like write_AC) and memory interaction (like mem_read) inherently increments the global cpuClock variable, acting as an accurate performance profiler.

// C macros force bit limits #define MASK16(val) ((val)&0xFFFF) #define MASK12(val) ((val)&0xFFF) void write_AC(int val) { AC = MASK16(val); cpuClock++; } void write_MAR(int val) { MAR = MASK12(val); cpuClock++; }

The FDE Cycle: Fetch & Decode

fetchDecodeExecute.c

The cycle engine lives here. The fetch() function dictates how exactly memory turns into an executable command.

  1. Push current PC to MAR.
  2. Read memory via data_bus.
  3. Store result in IR.
  4. Increment PC.

Next, decode() isolates the 4-bit opcode and 12-bit address variables from the 16-bit IR.

void fetch(void) { write_MAR(PC); data_bus = mem_read(MAR); write_IR(data_bus); write_PC(PC + 1); } void decode(void) { // Shift away lower 12 bits opcode = (IR >> 12) & 0xF; // Mask away top 4 bits write_MAR(IR & 0x0FFF); }

The FDE Cycle: Execution Router

fetchDecodeExecute.c

Once the opcode integer is parsed (0x1 through 0xD), the execute() function acts as a gigantic hardware multiplexer, triggering functions exported from instructions.c.

void execute(void) { switch (opcode) { case 0x1: LOAD(); break; case 0x2: STORE(); break; case 0x3: ADD(); break; case 0x4: SUBT(); break; case 0x5: IN(); break; case 0x6: OUT(); break; case 0x8: SKIPCOND(); break; case 0xA: CLEAR(); break; // ... Covers all 13 hex mappings } }

Direct Logic Operations

instructions.c

This implementation file defines the actual manipulation of registers. No logic is abstracted; the internal data_bus is explicitly simulated.

SKIPCOND Logic

Instead of dedicated conditional jumps, SKIPCOND peeks at the top bits of the address field (stored in MAR) to compare the AC against zero (using 0x000 for <0, 0x400 for ==0, and 0x800 for >0), skipping the PC ahead if true.

void ADD(void) { data_bus = mem_read(MAR); write_MBR(data_bus); data_bus = MBR; write_AC(AC + data_bus); } void SKIPCOND(void) { if (MAR == 0x000 && AC < 0) write_PC(PC+1); else if (MAR == 0x400 && AC == 0) write_PC(PC+1); else if (MAR == 0x800 && AC > 0) write_PC(PC+1); }

Indirect Addressing & State Output

instructions.c

In addition to standard instructions, this file manages "Indirect" pointer-following instructions (like ADDI or LOADI) and beautiful console visualization.

Following Pointers

In ADDI, the MAR initially holds an address that points to another address. The code intentionally calls mem_read(MAR) twice, updating the MAR with the pointer value in between reads.

void ADDI(void) { // Fetch pointer address data_bus = mem_read(MAR); // Follow the pointer write_MAR(data_bus); // Read real value & add data_bus = mem_read(MAR); write_MBR(data_bus); write_AC(MASK16(AC + MBR)); }

Text to Machine Code Translation

assembler.c

To create runnable programs, assembler.c reads textual instructions (like `"ADD 20"`) and constructs the explicit 16-bit binary equivalents.

  • sscanf splits the string into mnemonic string and operand integer.
  • strcmp compares the string to known opcodes.
  • It left-shifts the matched opcode by 12 bits (e.g., 0x3 << 12).
  • It bitwise-ORs the operand onto the bottom 12 bits.
int assemble(char *line) { char mnemonic[10]; int operand = 0; sscanf(line, "%s %d", mnemonic, &operand); if (strcmp(mnemonic, "LOAD") == 0) return MASK16((0x1 << 12) | MASK12(operand)); else if (strcmp(mnemonic, "ADD") == 0) return MASK16((0x3 << 12) | MASK12(operand)); //... Handles all formats }

Test Case Walkthrough

program.txt

Let's trace how the emulator executes the simple addition program loaded from program.txt.

; Addr Instruction 0x000 INPUT ; Prompt user -> AC 0x001 STORE 20 ; Save AC -> Memory[20] 0x002 INPUT ; Prompt user -> AC 0x003 ADD 20 ; AC = AC + Memory[20] 0x004 OUTPUT ; Print AC to console 0x005 HALT ; Stop execution

Execution Flow

  • 0x000: IN() pauses. User types 15. AC = 15.
  • 0x001: STORE() routes 15 from AC via MBR into memory[20].
  • 0x002: IN() pauses. User types 25. AC = 25.
  • 0x003: ADD() reads 15 from memory[20], and updates AC = 25 + 15 = 40.
  • 0x004: OUT() routes 40 to OutREG and prints to the terminal!
